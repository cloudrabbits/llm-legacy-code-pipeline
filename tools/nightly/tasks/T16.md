## 任务：P0 项定位说明与改动建议（降级档 —— 不产出可应用补丁）

【输入范围】T15 中标记为 **P0** 的前 1–2 项，及其涉及的源文件（由 input_range 预取原文）。

【角色定位（重要，别越界）】
本任务**不要求、也不要让模型产出可被 `git apply` 直接应用的 unified diff**。
实测证据（3 轮完整尝试全部失败）：模型会在 diff 里用省略号替代未改动行、或在多文件时
被输出预算截断，导致补丁必然 `corrupt`，无法应用。
正确做法：**只做"精确定位 + 改动说明"**，由人工/IDE 据此执行改动。补丁成环交给人。

【方法】
1. 对每项 P0，给出**精确的 `文件:行号` 定位** —— 这是本任务最高价值的产出，会进入事实库。
2. 用自然语言描述建议改动（做什么、为什么、明确"不动什么"），可附伪代码片段示意；
   **不要**把它包装成 unified diff 去要求可应用。
3. 每项附：风险、回滚方式、验证步骤。

【产出格式】
Markdown 文档：
- 二级标题（`##`）开头；
- 每个 P0 项一个 `###` 小节，内含：
  - **证据行**（硬要求）：`文件:行号 | <一句话结论/风险>`，必须精确、必须真实存在于预取原文；
  - 问题描述；建议改动；风险；回滚；验证。

【约束】
- 不得编造行号；引用到的 `文件:行号` 必须能在预取原文中找到对应位置。
- 不得改动业务逻辑语义；不得同时给出需改动超过 2 个文件的方案。
- 若某项无法给出精确行号，宁可写"未定位到具体行"，也不要臆造。
- 事实行缺失 / 定位明显编造 → 判定失败（这是白天人工能否直接行动的前提）。
